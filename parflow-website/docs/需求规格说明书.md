# ParFlow CONCN Share Platform 需求规格说明书

## 1. 文档目的与范围

本文规定 ParFlow 流域数据共享平台的业务规则、功能范围、数据库设计概要、验收要求及后续建设事项。依据当前前后端代码整理，不将已编写代码等同于已经完成公网部署。

平台目标：用户通过地图或流域编号找到所需流域，注册登录后按照共享规则获取完整裁切数据包；管理员管理账号、申请、共享规则、数据版本及网站内容。最终在服务器部署并向目标用户开放访问。

实现状态定义：**已实现**表示当前代码已有功能；**需配置验证**表示依赖数据、网络、邮件或服务器环境；**待完善**表示尚未形成完整功能。本文替代旧需求说明，后续变更直接更新本文件。

## 2. 用户角色与权限

| 角色 | 权限 |
|---|---|
| 游客 | 浏览首页、流域地图、流域详情、使用说明和公告；注册、登录 |
| 注册用户 | 游客权限；按规则下载、提交申请、查看个人申请和下载、接收站内通知、修改个人信息 |
| 管理员 | 用户权限；审核申请、管理普通账号、管理共享规则、查看任务与审计、维护双语内容、停止数据版本共享 |

后台权限由服务端检查，不能仅通过隐藏网页按钮控制。用户仅能访问自己的申请、任务、通知和文件会话。管理员角色不自动豁免数据下载资格检查。

## 3. 核心业务规则

### 3.1 流域级别与编号

系统共七级流域，编号为保留前导零的 14 位数字字符串。搜索只支持完整编号精确匹配，不支持名称、部分编号或模糊搜索。

| 网页显示级别 | 数据源 PFBAS 值 |
|---|---|
| 1 | 2 |
| 2 | 4 |
| 3 | 6 |
| 4 | 8 |
| 5 | 10 |
| 6 | 12 |
| 7 | 14 |

默认第 5、6、7 级为小流域；管理员可将小流域起始级别设为 1–7，包含选定级别及其后各级。网页显示“第几级流域”。API 中部分字段仍采用原始 PFBAS 值，见 API 文档。

### 3.2 下载资格

1. 下载必须登录；邮箱必须唯一，目前以账号限制额度，不进行自然人身份识别。
2. 每账号累计免审核获取两个不同小流域编码。同一编码可重复获取，不重复占用额度。
3. 新任务提交时预留小流域名额；首次签发下载会话后确认取得该编码资格。失败或取消且没有其他有效任务、结果引用时，可释放未激活的预留名额；已激活资格保留。
4. 大流域需申请审核；超过两个免费编码的小流域也可申请。小流域未用完名额时同样允许主动申请。
5. 每份申请对应一个流域和一个数据版本，可以多次申请，不设累计两次申请上限。
6. 审核通过的资格绑定账号、流域和版本，并有有效期；默认 168 小时，管理员可调整为 1–8760 小时。过期或撤销后重新申请。
7. 经审核取得额外小流域不增加免费名额；历史实现中的 approved_large 同时用于经审核的小流域和大流域。
8. 改变小流域阈值保留已取得的编码资格，但数据停止共享、账号停用或授权失效仍会阻止下载。

### 3.3 数据范围

只支持平台预定义流域，暂不支持上传边界、手绘范围或自定义流域。当前按完整数据包下载，暂不支持勾选变量或时间段。省市选择用于地图定位，不表示按照行政边界裁切。

### 3.4 下载用途

地图下载入口显示“填写下载用途”，包含流域编号、科研单位（必填，最多 100 字）、下载用途（必填，最多 200 字）、字数提示、条款确认和取消/下载按钮。输入去除首尾空白。

用途和单位保存于下载任务 request_snapshot 的 download_purpose、download_affiliation；不写入公开 ZIP。为兼容已有调用，后端允许同时省略这两个字段，提供任一字段时必须同时合法提供两个字段。已有申请记录下载及历史任务路径尚未统一为每次弹出用途表单，属于待完善项。管理员任务列表目前不展示用途详情。

## 5. 流程与状态

### 5.1 普通下载

登录 → 地图选择/搜索流域 → 下载数据 → 检查数据及资格 → 填写单位与用途并同意条款 → 下载 → 排队/裁切 → 准备完成 → 保存 ZIP。可以在“我的下载”继续查看和保存。

### 5.2 申请下载

选择流域 → 无直接资格时填写申请 → 待审核 → 管理员通过或驳回 → 通过后在有效期内下载。待审核申请可撤回；已通过授权可由管理员撤销。

申请字段：姓名 1–100 字、单位 1–255 字、用途（项目或论文）、项目名称或论文题目 1–255 字、项目负责人（1–255 字自由文本）或论文类型（硕士/博士/期刊论文）、申请理由 10–5000 字、项目 HTTP/HTTPS 链接选填最多 2000 字；联系邮箱取当前账号，不允许冒填他人邮箱。

申请状态：pending、approved、rejected、withdrawn、revoked。授权到期根据 authorization_expires_at 判断，不一定改变 approved 字段。

任务状态：queued、running、packaging、succeeded、failed、cancel_requested、cancelled、expired。状态不代表百分比进度；完成任务还需检查结果文件及授权有效性。

## 6. 下载包规格

文件名：`ParFlow_CONCN_Share_Platform_流域编号_YYYYMMDD.zip`，日期为实际下载请求的北京时间日期。ZIP 内一个流域编号目录，共 11 个文件：

| 文件 | 内容 |
|---|---|
| slopex.B.pfb、slopey.B.pfb | 两方向坡度 |
| bedrock.B.pfb | bedrock 裁切数据 |
| manning.B.pfb | 曼宁糙率 |
| subsurface.B.pfb | 地下介质 |
| mask.B.tif、mask.B.pfb | 流域掩膜 |
| B.pfsol、B.vtk | 计算域与可视化文件 |
| metadata.json | 流域、级别、版本、网格等元信息 |
| CITATION.txt | 引用要求与正式引用条目，正文由平台按数据版本生成 |

B 为 14 位编号。metadata.pfbas_level 为 1–7，concn_data_version 为 concn1.1；不含 boundary_version、clip_version、source_manifest_sha256、package_mode。ZIP 不含 README.txt、SHA256SUMS.txt；CITATION.txt 随包发布，正文由平台按数据版本的引用条目生成。服务器仍保留内部完整性校验，不因裁剪说明文本取消源数据校验。

新规范仅应用于新生成包；历史归档不就地改写。修改包规范后的新任务不复用旧规范归档。完整包是当前五类输入和掩膜/计算域配套文件，不表示包含完整 ParFlow 模拟工程、气象强迫或所有模型配置。

## 7. 数据库设计概要

数据库采用 MySQL，迁移脚本当前共 23 张表。编号以字符串保存；业务记录通过外键关联；任务及申请使用幂等键避免重复提交；时间按 UTC 保存，对用户展示时转换时区。二进制文件不存入 MySQL，数据库保存相对路径、大小、哈希、状态及版本信息。

| 领域 | 表 | 用途 |
|---|---|---|
| 身份 | users、auth_sessions、email_actions | 账号、登录会话、邮箱操作令牌 |
| 规则 | basin_levels、access_policies、platform_config | 级别映射、历史策略、当前配置 |
| 地理 | watersheds、administrative_regions | 流域属性与省市定位 |
| 数据 | dataset_versions、dataset_files、watershed_datasets | 数据版本、文件清单、流域可用性 |
| 资格 | small_basin_slots | 每账号两个不同编码的预留和已取得资格 |
| 申请 | large_basin_applications、application_reviews | 所有需审核流域的申请和审核记录 |
| 处理 | download_jobs、job_attempts、task_outbox | 任务、执行尝试、持久化队列 |
| 结果 | result_archives、download_sessions、usage_daily | 归档、短时下载授权、每日统计 |
| 内容 | content_pages、notification_reads、audit_logs | 双语内容、通知已读状态、操作审计 |

下载用途属于 download_jobs.request_snapshot JSON 新增字段，无需新增表。通知事件来自审核和归档记录，notification_reads 仅存用户阅读状态。large_basin_applications 表名沿用历史命名，但支持小流域申请。

关键关系：用户一对多申请/任务/会话；流域通过 watershed_datasets 关联版本；申请绑定用户、流域、版本；任务关联可选申请、执行尝试和归档；下载会话同时绑定用户、任务、归档。详细字段见[数据库逐字段说明](数据库说明.md)及迁移脚本。

## 8. 非功能要求

- 安全：服务端校验所有权、账号状态及授权；写请求带防跨站请求头；登录及下载令牌保存哈希；密码和服务器凭据不得写进文档或公开包。
- 一致性：并发提交不得使免费编码超过两个；同一幂等键不同请求返回冲突；资格、预留和队列事务保持一致。
- 可靠性：任务在独立工作进程执行，有心跳、超时、取消及过期清理；磁盘不足、文件过大或科学校验失败应返回明确状态。
- 性能：地图边界支持压缩和缓存，绘制分批处理；高等级全量边界仍较大。目标并发数、峰值下载带宽和响应时限需在服务器实测后确定，未承诺固定人数。
- 部署：前端生产构建、Web 服务、任务进程、MySQL 和数据目录均须就绪。公网 HTTPS、邮件及访问控制需部署验证。
- 可维护性：修改规则保留历史策略；对文件规范变更调整包修订标识；备份须同时覆盖数据库、源数据、归档与配置。

## 9. 验收清单

| 场景 | 期望结果 |
|---|---|
| 新用户注册 | 成功后回到登录，不获得登录 Cookie |
| 搜索错误长度、字母、缺失编号 | 提示输入错误，不执行模糊检索 |
| 搜索 A 后点击 B | A 橙色、B 绿色；返回地图保留状态 |
| 第三个不同小流域 | 不能免审核获取，可提交申请 |
| 重复同一编码 | 不新增免费编码占用 |
| 他人任务、申请、文件会话 | 拒绝访问，不泄漏内容 |
| 授权到期/撤销、版本停止共享 | 不再发放有效文件下载 |
| 下载用途为空 | 地图弹窗不能提交；正常提交后数据库保存用途 |
| 新 ZIP | 命名正确、10 文件、级别 1–7、无说明/引用/哈希文本 |
| 账号搜索 | 用户名/邮箱均可匹配，只有一层输入框边框 |
| 打包中切换页面 | 后台继续，个人下载页面可查看 |
| 邮件服务缺失 | 明确告知不可用，不假装邮件已发送 |

## 10. 待完善与部署前确认

1. 各下载入口统一用途采集、管理员用途查看/导出、后端统一必填校验。
2. 数据集清单仍可能包含历史生成文件定义；实际 ZIP 以当前打包规则为准，后续统一目录展示。
3. 正式数据许可及引用内容需维护；历史许可文字可能仍引用已移除的 CITATION.txt。
4. 源数据新版本发布工具完善，跨 Windows/Linux 的科学工具构建及版本校验验收。
5. 邮件发送配置、域名/HTTPS、反向代理可信来源、进程守护、备份恢复及压力测试。
6. 对外部署需要可达网络入口、域名或地址、HTTPS 及相应运维权限；反向代理本身不能使不可路由的地址变为公网地址。
7. 自定义流域、选变量下载、其他数据类型、多账号自然人识别均不在当前已实现范围。
