# 科学裁切工具说明

本文介绍裁切模块、数据路径、命令行使用和输出约定。模型背景、文献引用与流域分级见 [项目首页](../README.md)。

## 当前模块和执行链路

| 文件 | 作用 |
| --- | --- |
| `concnshare/config.py` | ClipConfig，数据路径、PFB 名称、网格参数；字段名默认 PFBAS_ID |
| `concnshare/generate_mask.py` | 用目标流域几何和模板栅格生成掩膜与窗口位置 |
| `concnshare/crop_pfb.py` | 按窗口和掩膜裁切五类源 PFB |
| `concnshare/run_two.py` | 完整流程：生成掩膜 → 转 PFB → 转域文件 → 裁切 → 写 metadata |
| `backend/datahub/workers/clip.py` | 网站任务适配：原始输入核验、调用工具、规范化公开元信息、打 ZIP |
| `backend/datahub/workers/queue.py` | 数据库领任务、心跳、子进程、状态及归档维护 |

完整目录见 [项目结构说明](项目结构与文件说明.md)，网站安装启动见 [部署说明](部署说明-v1.0.md)。

## generate_mask.py 的实际处理

1. 从 Shapefile 中按编码字段筛选目标流域；多条几何合并，无匹配则报错。
2. 将流域几何投影到模板 GeoTIFF 的 CRS。
3. 要求模板为北向上的规则网格，拒绝旋转网格；expand 必须为非负整数，默认 1。
4. 用 geometry_window 对齐整数像元窗口，默认向外扩展 1 个像元，窗口以源栅格范围为界。
5. 用 geometry_mask 栅格化，all_touched=False，流域内 1、外部 0；没有有效像元时报错。
6. 写单波段 uint8、LZW 压缩的 GeoTIFF，同时写 row_min、col_min、height、width 到位置 JSON。

完整流程随后对 TIFF 行方向翻转，生成符合 PFB 方向的掩膜；裁切工具使用同一窗口处理源数据。pos.json 和 *.dist 是中间文件，完整流程成功后清理，不属于最终下载包。

## 环境与路径

已有环境使用 `conda activate concnshare`。全新环境才执行根目录 environment.yaml 和 backend/requirements/worker.txt 的安装步骤，不重复初始化现有数据库。

网站 worker 会通过 backend/datahub/config.py 加载 backend/.env；**直接执行独立科学 CLI 不会自动加载这个文件**。必须先配置科学路径；不要把含密码的 .env 当 shell 脚本 source。

```bash
cd /path/to/ParFlow-CONCN-Share-Platform
conda activate concnshare
export CONCN_SHP_DIR=/path/to/data/PFBAS/shp
export CONCN_TIF_DIR=/path/to/data/PFBAS/geotiff
export CONCN_INPUT_PFB_DIR=/path/to/data/inputs
export PARFLOW_PFMASK_CMD=/path/to/parflow/bin/pfmask-to-pfsol
```

ClipConfig 的内置路径不保证适用于其他机器。部署时应显式配置科学数据路径，输入数据只读使用，输出目录由运行账号管理。

## 独立完整裁切命令

以下为独立裁切调用示例。使用集群时，按集群规范将命令放入作业脚本并通过调度器提交；分区和资源需求由部署环境决定。网站 worker 的运行位置也应遵循该环境的服务管理要求。

```bash
python -m concnshare.run_two 03030109050100 --output-dir /path/to/ParFlow-CONCN-Share-Platform/outputs
```

可用已安装的 `run_two` 命令代替模块调用。省略编号时交互输入；批处理应明确提供编号。输出目录默认 OUTPUT_DIR 环境变量，否则当前工作目录下 outputs。`--overwrite` 会删除该编码已有输出目录后重建，只有明确需要覆盖时才添加。

## 仅生成掩膜

独立 CLI 默认字段是 PFBAS，而完整流程 ClipConfig 默认 PFBAS_ID；当前数据应显式传 `--field PFBAS_ID`。输出父目录需提前存在。例如在任务脚本中：

```bash
mkdir -p /path/to/ParFlow-CONCN-Share-Platform/outputs/mask-check
python -m concnshare.generate_mask \
  --shp "$CONCN_SHP_DIR/PFBAS12.shp" \
  --code 03030109050100 --field PFBAS_ID \
  --tif "$CONCN_TIF_DIR/PFBAS12.tif" \
  --out_mask /path/to/ParFlow-CONCN-Share-Platform/outputs/mask-check/mask.tif \
  --out_json /path/to/ParFlow-CONCN-Share-Platform/outputs/mask-check/pos.json \
  --expand 1
```

此命令只生成 TIFF 和位置 JSON，不生成完整下载包。

## 独立输出与网站下载包的区别

独立 run_two 生成 `outputs/编号/` 内的五类 PFB、mask TIFF/PFB、VTK、PFSOL 和 metadata.json，不自动创建网站任务或 ZIP。其 metadata 的 pfbas_level 是内部 2/4/…/14，版本取 CONCN_DATA_VERSION（默认 1.1）。

网站 worker 在打包前用 public_metadata 将级别转为 1–7，将公开版本标识改为 concn1.1。任务结果位于 backend/jobs/任务ID/attempt-次数/result.zip；文件列表及命名见 [下载包内容与文字维护](下载包内容与文字维护.md)。

## 摘要检查范围

网站任务核验五个源 PFB 的完整集合和摘要，并对快照中对应级别的边界/模板资产核验摘要。历史 pipeline_sha256 与 pfmask_sha256 不再比较，直接运行当前 Python 工具和 PARFLOW_PFMASK_CMD。缺失源文件、源摘要不一致、转换器执行失败、缺少必需输出仍会导致失败。

独立 run_two 不执行网站发布快照的摘要核验；它检查编码、所需文件和科学处理条件。不能把独立 CLI 成功等同于网站授权下载链路完整验收。
