# 部署说明

本文面向 Linux 部署，使用 Conda、MySQL、Waitress 和独立裁切 worker。示例中的路径、用户名、端口和域名均需按部署环境配置。代码仓库不包含业务数据库、科学源数据或访问密钥。

## 1. 运行架构

浏览器连接 Waitress；Waitress 提供构建后的 Vue 页面与 Flask API。MySQL 保存账号、目录、申请、授权和任务记录；worker 读取任务并调用科学裁切工具，结果写入文件系统。网站、worker、MySQL 是独立进程，必须分别管理。

示例使用本机端口 8000。对外访问地址由 CONCN_PUBLIC_URL 指定，监听由 CONCN_HOST 和 CONCN_PORT 控制。监听所有网卡不代表网络防火墙已放行。

## 2. 环境准备

需要 Python 3.12、MySQL 8.4 系列及满足 frontend/package.json 要求的 Node.js。pfmask-to-pfsol 必须是目标 Linux 环境可执行的程序，科学源数据需单独准备。

在项目根目录执行：

```bash
conda env create -f environment.yaml
conda activate concnshare
python -m pip install -r backend/requirements/worker.txt
conda install -c conda-forge nodejs=22
npm --prefix frontend ci
```

已有环境直接激活，不重复创建。worker.txt 包含网站依赖；仅运行网站可安装 web.txt。部署目录和数据目录须具备相应读写权限。

## 3. MySQL 与业务库

MySQL 服务的安装和启动方式取决于操作系统和部署权限。使用系统服务或用户级实例均可，但应确认连接地址、端口及备份路径。MySQL 物理数据位置由服务端 datadir 配置决定，不是仓库中的 database 目录。

### 全新站点

先启动 MySQL，确保没有同名业务库、测试库和应用用户，且 backend/.env 不存在。从 backend 目录运行：

```bash
python -m datahub.cli bootstrap
```

输入 MySQL 管理员密码。该命令创建 concn_datahub、concn_datahub_test、表结构、默认记录和应用账号，并生成 backend/.env 与私有管理员凭据文件。它会拒绝覆盖已有配置或数据库。连接管理账号的环境参数见 backend/datahub/repositories/db.py；非默认 MySQL 地址需先配置 MYSQL_HOST/MYSQL_PORT。

### 继承现有站点

按 [数据库继承与部署交接](数据库继承与部署交接.md) 导出、恢复业务库，并创建目标应用账号。恢复后不要运行 bootstrap 或重新写入默认 seeds。SQL 不包含科学文件和历史 ZIP。

## 4. 配置

全新 bootstrap 后编辑生成的 backend/.env；恢复已有数据库时从 backend/.env.example 创建本地配置。不要覆盖已有有效凭据，不把 .env 当 shell 脚本 source。

| 配置项 | 用途 |
| --- | --- |
| MYSQL_HOST / MYSQL_PORT | 数据库服务地址和端口 |
| MYSQL_DATABASE | 业务库名称，通常为 concn_datahub |
| MYSQL_USER / MYSQL_PASSWORD | 专用应用账号及密码，不使用数据库 root 运行网站 |
| CONCN_HOST / CONCN_PORT | 网站监听地址及端口 |
| CONCN_PUBLIC_URL | 浏览器实际使用的网站来源，包含协议和必要的端口 |
| CONCN_ENV | 运行模式；production 有 HTTPS/Cookie 配置检查 |
| CONCN_COOKIE_SECURE | HTTPS 部署设为 1；纯 HTTP 测试设为 0 |
| CONCN_REQUIRE_VERIFIED_EMAIL | 是否要求邮箱验证，需与 SMTP 配置及实际流程配套 |
| CONCN_SHP_DIR | PFBAS Shapefile 及其配套文件所在目录 |
| CONCN_TIF_DIR | PFBAS 模板 GeoTIFF 目录 |
| CONCN_INPUT_PFB_DIR | 五个原始科学 PFB 所在目录 |
| PARFLOW_PFMASK_CMD | Linux pfmask-to-pfsol 可执行文件路径 |
| CONCN_JOB_ROOT | 任务输出根目录，建议使用明确的绝对路径 |
| SMTP_* | 邮件服务参数 |

本机 HTTP 测试可使用以下非敏感配置：

```dotenv
CONCN_HOST=127.0.0.1
CONCN_PORT=8000
CONCN_PUBLIC_URL=http://127.0.0.1:8000
CONCN_ENV=development
CONCN_COOKIE_SECURE=0
```

需要直接接受远端请求时可将 CONCN_HOST 设为 0.0.0.0，并把 PUBLIC_URL 改为实际可达地址。公开服务应配置 HTTPS、访问策略和邮件服务，不能将开发模式示例直接视为完整生产配置。

前端从 frontend/.env.example 创建 frontend/.env.local。VITE_TIANDITU_KEY 用于地图；VITE_API_TARGET 仅用于开发代理。修改前端变量后需要重新构建。密钥、凭据与本地配置不提交到仓库。

## 5. 数据目录和发布

恢复业务数据库时保留其数据目录关系，并将科学路径指向匹配源文件。全新站点可通过 import-catalog 导入目录；发布还需版本和文件清单。publish-local 仅用于 development 模式、本地 MySQL 的验证发布，不能当作通用生产发布流程。命令与限制见 [脚本索引](../scripts/README.md)。

worker 检查原始 PFB、对应级别边界/模板摘要与输出完整性，不比较历史工具代码或转换器摘要。工具变化后仍应验证真实科学输出。

## 6. 构建与前台启动

在项目根目录激活环境，构建页面：

```bash
conda activate concnshare
bash scripts/run-linux.sh build
```

两个独立终端分别运行：

```bash
bash scripts/run-linux.sh web
```

```bash
bash scripts/run-linux.sh worker
```

脚本保持前台运行，Ctrl+C 停止对应进程。关闭终端可能使进程退出。网页由后端提供 frontend/dist，不需要另外运行 Vite；Vite 仅用于前端开发。

## 7. 后台运行与日志

先确认没有重复的网站或 worker 进程。在项目根目录激活环境后执行，确保 CONDA_PREFIX 指向 concnshare：

```bash
conda activate concnshare
umask 077
mkdir -p .local/runtime
nohup "$CONDA_PREFIX/bin/python" -B -u backend/app.py \
  >> .local/runtime/backend.log 2>&1 < /dev/null &
echo $! > .local/runtime/backend.pid
```

worker 从 backend 目录启动：

```bash
cd backend
nohup "$CONDA_PREFIX/bin/python" -B -u -m datahub.workers.queue \
  >> ../.local/runtime/worker.log 2>&1 < /dev/null &
echo $! > ../.local/runtime/worker.pid
cd ..
```

nohup 用于脱离终端后继续运行，不提供崩溃重启或开机启动，也不绕过集群的作业和会话策略。集群部署应遵循管理员对节点和任务调度的要求。需持续托管时由运维配置 systemd 等服务管理器；仓库未附带可直接安装的服务单元。

## 8. 检查、停止和重启

在项目根目录检查：

```bash
bash scripts/run-linux.sh check
ss -ltnp 'sport = :8000'
ps -u "$USER" -o pid,args | rg '[p]ython.*(app.py|datahub.workers.queue)'
tail -n 50 .local/runtime/backend.log
```

端口按实际配置替换。check 读取 backend/.env 并请求本机健康接口，不执行裁切任务。健康检查不能代替浏览器、下载、邮件和远端网络验收。worker --once 会执行真实任务，不是只读健康检查。

停止前核实进程命令、PID 和工作目录，再执行 `kill -TERM 实际PID`。PID 文件可能过期，不应直接信任旧值；不要批量终止所有 Python 进程。前台服务可用 Ctrl+C 停止。worker 应在活动任务结束后停止。

停止网站不会关闭 worker 或 MySQL。修改后端配置后重启相应常驻进程；前端修改需重新 build 并刷新浏览器。若启动失败，检查日志，不通过忽略错误确认“启动成功”。

## 9. 远端访问与 SSH 转发

直接访问需要目标主机、端口、路由、防火墙和网络访问策略均允许。SSH 端口可达不代表网站端口可达；反向代理也不能自动解决路由隔离。不要将 MySQL 端口直接作为浏览器入口。

有服务器 SSH 权限的测试者可建立本地转发，替换用户名和服务器主机名，目标端口与后端保持一致：

```bash
ssh -N -o ExitOnForwardFailure=yes -L 18000:127.0.0.1:8000 user@server.example.com
```

保持窗口打开，在该测试者电脑访问 http://127.0.0.1:18000。-N 持续等待是正常行为，Ctrl+C 结束隧道。网站仍需运行且服务器允许 TCP 转发；测试者使用各自 SSH 账号。

地图 SDK 和瓦片由浏览器直接请求外部服务，SSH 转发本网站不会代理这些请求。默认地图为地形；配置天地图密钥时失败会显示错误并可重试，无密钥时采用既有 Leaflet 模式。图片加载失败应查看浏览器网络错误，不能仅用网站健康检查判断。
